# Lessons

Patterns learned the hard way on this repo. Add an entry after any correction.

## 2026-10-10 — PR #8 (issue #1, verification baseline)

- **Regenerate mocks whenever a mocked class's public API changes.** The suite went from green to 84 failures because `GameState` gained members and the committed `*.mocks.dart` files were not regenerated; generated mocks throw on unknown members. Run `dart run build_runner build --delete-conflicting-outputs` and commit the result in the same pull request.
- **Run the whole suite, not just the tests for the file you touched.** The breakage went unnoticed for months because only targeted test files were run after each feature.
- **`flutter_test`'s `group()` has no `tags` parameter; `testWidgets()` does.** Tag individual tests. A plan written without a toolchain got this wrong.
- **A plan that was never executed against a real toolchain is a prediction.** The plan for issue #1 was written by reading code only. It was right about the cause and wrong about one API detail. Measure before trusting it.
- **Untracking a file with `git rm --cached` deletes it from every other checkout on the next pull.** For a file people need locally (for example `.claude/settings.local.json`), say so in the pull request and give the restore command.
- **Goldens that render time-dependent state cannot gate CI.** Special-peg shimmer reads `DateTime.now()` during paint, so two golden tests fail on every run. Inject a clock before relying on them.

## 2026-10-11 — PR #12 (issue #2, achievement toasts)

- **Reproduce every defect a plan lists before fixing it.** The plan for issue #2 named four defects. Three were real. The fourth (`_dismiss` calling `onDismissed` twice) did not reproduce: a second `AnimationController.reverse()` cancels the first one's future, which then never completes. A probe test that counted callbacks settled it in a minute.
- **Do not match short numeric text with `find.textContaining`.** `find.textContaining('1/2')` also matched the unlock date `10/11/2026`, so the test failed only on some calendar dates and only in CI's time zone. Use `find.text` for an exact label. To reproduce a date-dependent CI failure locally, run the test with `TZ=UTC`.
- **Never run `rm` with a wildcard, even in a git-ignored scratch directory.** Write to new file names, or delete files by explicit name. (Correction from Frank during this run.)
- **Bare `flutter analyze` is unusable locally.** It also analyzes the SDK checkout in `tools/flutter` and reports about 11,500 issues. Run `flutter analyze --no-fatal-infos --no-fatal-warnings lib test` until issue #10 adds an exclude.
- **A reviewer told "do not modify tracked files" may still run a code generator.** The cross-family reviewer ran `build_runner`, which rewrote the committed mocks; it restored them, but only by regenerating. Name `build_runner`, formatters and fixers explicitly in the review prompt, and check `git status` after every review.
- **The app can be demoed without a desktop toolchain.** This machine cannot build the Linux target. `flutter build web --no-tree-shake-icons`, serve `build/web` on localhost, and drive it with `agent-browser mouse move/down/up` by coordinates (Flutter web paints to a canvas, so there are no elements to click). Saved state lives in the browser's `localStorage` under `flutter.achievements` and can be seeded to set up a scenario.

## 2026-10-11 — PR #17 (issue #3, bonus ball spawn)

- **Simulate a gameplay change across many levels, not only the one in the plan.** The plan's tests check where bonus balls appear. Stepping the real `PhysicsEngine` over levels 1–30 showed something neither the plan nor the tests could: balls come to rest between pegs (2.4% of launched balls, 23% on level 5), and bonus balls now meet that bug because they finally touch pegs. Filed as #16. Ask what a fix newly exposes, not only whether it does what the issue says.
- **A probe test does not have to live in the repo.** From the package directory, `flutter test /absolute/path/probe_test.dart` resolves `package:pachinko_game/...` imports. Keep probes in a scratch directory: the tree stays clean, the full suite does not pick them up, and the same file runs against `master` in the main checkout for a before-and-after.
- **A state that cannot be reached by playing can still be shown.** Pump the real `PachinkoBoard` in a throwaway widget test, set up the state through `GameState`, and write a PNG with `matchesGoldenFile('<absolute path>')` under `--update-goldens`. Text is drawn as blocks by the test font; shapes and colours are real.
- **`flutter test` needs `-r failures-only` or `-r expanded` when its output is piped.** The default reporter rewrites one line with carriage returns, so `grep` returns the whole run as a single line.
- **`command | tail; echo $?` reports `tail`'s exit code.** Redirect the output to a file and read `$?` straight after the command when the exit code is the thing being checked.

## 2026-10-11 — PR #19 (issue #4, restart resets launcher)

- **Compile a plan's test code before trusting it.** The plan's two `GameState` tests used `Colors.white`, which is ambiguous in any file that imports both `flutter/material.dart` and `vector_math_64.dart` (both export `Colors`). Use `const Color(0xFF...)` there, as the rest of `game_state_test.dart` does. A compile error in one test file also hides that file's other tests from the RED run, so read the load errors before counting failures.
- **Target mutations by line number, not by "the nth occurrence of this text".** Deleting the first `_ballCountHighlighted = false;` removed the field declaration (a compile error that looks like a killed mutant), and the third `_ballLauncher.reset();` was the pre-existing one in `_updatePhysics`. Run `grep -n` first and confirm each mutation lands on a line the branch added.
- **Ask what a fix un-hides.** Resetting the launcher on `selectLevel`/`nextLevel` turned a soft-lock into a ball that carries over into the new level, because `loadLevel()` never cleared balls in play. A real-object probe run on the branch and on `master` showed both behaviours. Filed as #20.
- **The game screen's buttons move while a ball is in play.** At a 420x800 viewport the bottom row is Back (138) and Restart (281) when ready, and Back (102), Pause (210), Restart (317) while playing, all at y=764. The launcher is at (377, 590) and Play on the menu at (210, 304). A tap aimed at the ready-state Restart lands between two buttons during play.
- **Do a warm-up launch before a demo that reads the ball counter.** The first launch on a fresh origin unlocks "First Launch", and its toast covers the header for 3.5 seconds (issue #13). Each port is its own origin, so a second build served on another port starts with empty `localStorage`.
- **`pkill -f <pattern>` kills the shell that runs it when the pattern appears in that shell's own command line.** It took out the rest of a compound command and left one of two servers running. Find the pid with `ss -ltnp` and `kill` it.
- **A stale `.git/index.lock` in the main checkout can outlive a cross-family review.** The reviewer worked in its own copy under `/tmp/opencode` and left the worktree clean, but an empty lock dated inside its run blocked the post-merge `git pull`. Check `pgrep -x git` and the lock's mtime, then remove that one file.
- **Search for a method's callers by bare name, not with parentheses.** `grep "nextLevel()"` found no UI caller, and issue #20 and PR #19 said so. The Next Level button uses a tear-off, `onPressed: gameManager.nextLevel`, which has no parentheses. Both texts were corrected on 2026-10-10. (Correction found during the graphics review, #22.)
- **When an issue limits which files may change, documentation goes in the follow-up docs pull request.** The new rule for `CLAUDE.md` (transitions reset the launcher, effects are cleared in `_clearEffects()`) was held back from PR #19 and lands with these lessons, as in #15 and #18.

## 2026-10-10 — graphics review (issue #22)

- **Take a mock-up's geometry from the painter, not from a similarly named constant.** The neon parlor mock-up drew the launch channel's inner wall up to `launchChannelEndY` (110). The painter stops that wall at y = 135, and Frank rejected the mock-up because the mouth under the dome looked too narrow for a ball. Read the `draw*` method before drawing anything it draws. (Correction from Frank.)
- **Take a layout percentage from the pixels, and say what it measures.** Issue #22 first said the board uses about 57% of the screen height. Scanning one column of the screenshot for colour changes gave 68% for the board panel; 57% was the span from the dome to the top of the slots. The pegs span 24%. Name both ends of any measurement in the text.

## 2026-10-10 — PR #34 (issue #25, colour roles and the Oxanium font)

- **`FontWeight` does not drive a variable font's weight axis.** A probe test measured the same text width at w400 and w800 with the variable Oxanium file, and a different one only with `FontVariation('wght', 800)`. Existing code sets weight with `fontWeight:`, so the fix was to ship static instances: `uvx --from fonttools fonttools varLib.instancer <font> wght=700 --update-name-table`, declared with `weight: 700` in `pubspec.yaml`. Check the licence for a reserved font name before renaming or instancing a font.
- **Do not edit the working tree while a cross-family review is running.** The reviewer gets the diff inline but also reads the files, and it reported fixes made during its run as "stranded uncommitted". Commit first, or hold the edits until it finishes. Run mutation checks in a separate detached worktree (`git worktree add --detach`) for the same reason.
- **Make a mutation script match exact text and assert it occurs once.** A script that takes (file, exact text, replacement, test file) for each mutation, restores the file in a `finally`, and prints the survivors ran twelve mutations unattended with no wrong-line hits.
- **A wider font moves everything below it.** Under Oxanium the menu title wrapped to two lines and the Play button moved 93 px, so a scripted tap missed and two screenshots came out identical. Compare file sizes or look at the first capture before trusting a scripted sequence.
- **Wait about 20 seconds after `adb install` before the first screenshot.** Eight seconds caught the splash screen.
- **`gh` cannot attach an image to a pull request.** Screenshots go on the `pr-assets` branch, which holds no code, and the description links them by raw URL. The branch can be deleted once the pull requests that use it are merged.
- **Give the exact command with any analyzer count.** The description said "96 issues, down from 98"; the reviewer ran a different invocation and counted 107. The local command is `flutter analyze --no-fatal-infos --no-fatal-warnings lib test`.
- **Check that an acceptance criterion belongs to the slice before filing it.** Issue #25 first asked for the screens' literal text sizes to move onto the type scale, which is #32's work. It was corrected before implementation started.

## 2026-10-11 — PR #36 (issue #5, per-level score accounting)

- **A level past the first may not be finishable on a device.** Three attempts at level 2 on the emulator each ended with a ball at rest on a peg (#16). Show what happens at the end of a level with a probe test through the real services instead: `SharedPreferences.setMockInitialValues({})`, a real `StorageService`, `AchievementService.create(prefs)` and a real `GameManager`. Spend each ball with `gameState.launchBall(ball)` then `removeBall(ball)` and wait 40 ms for a loop tick; call `manager.resumeGame()` after `nextLevel()` to restart the loop. Run the same file from the main checkout for the behaviour on `master`.
- **Do not detect a stopped ball by comparing two screenshots.** Prize pegs shimmer, so the frames always differ. Time how long the Pause button stays on screen; a ball in play for more than 30 seconds has stopped.
- **Launch power is the length of the drag.** With `adb shell input swipe`, 70 to 120 px is a weak launch and 300 px or more is full power. Different powers reach different pegs, so vary it when one launch keeps ending in the same place.
- **Borrow a generated mock from another test's mocks file.** `import '../screens/high_scores_screen_test.mocks.dart' show MockStorageService;` gave `game_manager_test.dart` a storage mock without adding the class to its own `@GenerateMocks` list and regenerating.
- **Update the audit index when an issue closes.** The table in #7 still listed #4 as TODO a day after it merged. Change the row in the same step that files the loose ends.
- **Label an issue `needs-owner` when it waits on a product decision.** The label did not exist until #37 needed it. Issue discovery skips it and reports the issue as gated.

## 2026-10-11 — PR #40 (issue #6, game loop lifecycle)

- **A plan's claim that no test depends on a behaviour needs a run, not a search.** The plan for #6 named "a test asserts `canLaunchBall` is true with a ball in play" as a STOP condition. No test asserts it, and a search for the getter finds nothing wrong. Five `GameState` tests still depended on it: their setup launches a ball, forces the phase with `updatePhase(GamePhase.ready)` and launches again. Make the change and run the whole suite before believing the plan.
- **At a STOP condition, commit what does not depend on it, report on the issue, then ask.** Steps 1 to 4 were committed and green before the question went to Frank. His answer was none of the options offered: make the rule a setting (`GameState.singleBallLaunch`, on by default) and have the old tests turn it off. When a new rule collides with existing tests, offer "make it a setting" as an option.
- **Test every site of a repeated line, not one of them.** The plan's test covered the flag reset in `resetGame` only. The same line sits in `startGame`, `nextLevel` and `selectLevel`, and without it the next level could never end. A loop over the four transitions generates one test each, and the mutation run then kills all four.
- **Write a demo note after the command it describes.** A note quoted a popup position from an earlier run (y=559.1); the recorded run printed 559.2, and three Showboat entries had to be popped and redone. Timing-dependent numbers differ between runs.
- **Do not cut a reviewer's output at a heading matched from the start of a line.** opencode's narration ran straight into `## Review` on the same line, so `sed -n '/^## Review/,$p'` matched nothing and the PR comment was posted with only its title. Find the marker with a substring search and check the body's length before posting.
- **`pgrep -af` prints whole command lines, including another session's entire review prompt.** Use `pgrep -x <name>` or `pgrep -c`.
- **Read a compound command to the end before running it.** A stray `git checkout --detach` was appended to a command in the main checkout. It failed only because a stale `.git/index.lock` was in the way. During a worktree run, commands in the main checkout should only read.
- **The stale `.git/index.lock` came back, dated a minute before the review started.** So the reviewer is not its only cause. A commit in one worktree while `git worktree add` ran from a background shell is the likely one; this was not verified.
- **Game screen coordinates at 420x800 since the Oxanium change:** Play on the menu is at (210, 300), the launcher drag runs from (377, 590) to (377, 700), and Pause and Resume are at (210, 764). A ball takes up to 12 seconds to land.

## 2026-10-11 — PR #44 (issue #16, balls at rest between pegs)

- **When a generator changes, print what it produces on `master` and on the branch.** A probe that counted pegs and prize pegs per level, written to see how much the new spacing rule cost, showed that 30 of the first 100 levels on `master` had no prize peg at all, and that the fix would have made it 40. Nothing in the suite checked it: the tests that looked at prize pegs used level 1 and allowed zero.
- **Find the cause with a probe that says where, not only how many.** Printing the pegs each stuck ball was touching, and the gap between them, turned "2.4% of balls stick" into "every one is on two pegs less than a ball's width apart". That settled the choice the issue left open (guard, generator, or both) in favour of the generator alone.
- **Do not state a test's limit with the constant it guards.** The first version of the gap test required every gap to be at least `GameConstants.minPegGap`, so lowering the constant to 10 passed it. Assert the physical quantity (wider than the ball) and give the constant its own test.
- **A mutation that fails to compile is not a kill, and the script should say so.** One of fifteen mutations left a nullable variable unpromoted; the test file failed to load and the script printed KILLED. A failing entry that starts with `loading` is a compile error. This is the second time (see PR #19). Treat it as a survivor in the script.
- **`diff-cover` counts a line as changed when only its trailing whitespace changed.** Editing a block stripped the trailing spaces from blank and continuation lines nearby, and two old, unreachable lines showed up as uncovered new code. `git diff -w --stat` shows how much of a diff is whitespace.
- **A level can be played to the end unattended in the web build.** Thirty drags of the launcher 8 seconds apart finish a 20-ball round with its bonus; a drag while a ball is in play is ignored, so the extra ones cost nothing. Level tiles in the picker at 420x800 are 75 px apart starting at (97, 279); level 5 is at (97, 354).
- **Run the wider probe before deciding a safety net is unnecessary.** The tests cover levels 1 to 30. A copy of the probe over levels 31 to 300 (263,250 balls, 16 seconds) and of the layout probe over levels 1 to 3,000 is what supported shipping without a guard.

## 2026-10-11 — PR #48 (issue #9, golden tests)

- **Run a mutation check that fails golden tests in its own worktree.** The check ran in the branch's worktree right after the commits and left difference images in `test/widgets/failures/`. The cross-family reviewer found them, saw that they were newer than the commits and matched the committed baselines, and asked for changes on the grounds that the goldens might flake. Twenty clean runs and the timestamps settled it, at the cost of a second review pass. The directory is git-ignored, so `git status` does not show it.
- **Answer a reviewer in the same session.** `ask-opencode.sh -s <session id>` (the id is on the first line of the earlier call's stderr) took the evidence and returned a new verdict in about a minute. A fresh review would have taken five and started from nothing.
- **Before removing a stale `.git/index.lock`, look at what each git process is working on.** `pgrep -x git` counts every git on the machine; one was running in another repository for another session, and the lock was removed anyway because the command did not wait for the answer. Check `readlink /proc/<pid>/cwd` for each, and make the `rm` conditional on none of them being in this repository or its worktrees.
- **The lock appears during cross-family reviews, not before them.** Three more appeared in this run, each dated inside a review window, each empty. The earlier note that one was dated before a review started was probably the clock: timestamps printed by `date` and by `ls` in this environment disagree by minutes.
- **Showboat runs `exec` blocks with a different `python3`.** A script that imported Pillow worked from the shell and failed inside `showboat exec`. Use the interpreter's absolute path (`python3 -c "import sys; print(sys.executable)"`).
- **Golden baselines generated on this machine match on the GitHub runner.** Both are x86-64 Linux on Flutter 3.38.1 and the tests draw with the test font. All ten matched on the first CI run.
- **To show that something still animates, compare frames by pixel.** Six screenshots half a second apart, `ImageChops.difference` between neighbours, and the mean colour of the changed area gave "every frame differs, only around the prize pegs, dimming then brightening". Two screenshots side by side show nothing a reader can see.

## 2026-10-11 — PR #50 (issue #10, analyzer warnings)

- **The analyzer command is now `flutter analyze --no-fatal-infos`, with no path.** It works locally since `analysis_options.yaml` excludes `tools/flutter/**`: 89 issues, all info level, in a few seconds. The earlier lessons that give `flutter analyze --no-fatal-infos --no-fatal-warnings lib test` describe the state before this change.
- **An unused variable in a test is sometimes a missing assertion.** Eleven of twelve were dead captures and were removed. The twelfth, `initialVelocity`, sat beside a comment that was wrong (it said a random deflection is applied to a separating ball) and an assertion that only checked a sign. Read what the variable was for before deleting it.
- **`ln -s <target> <name>` puts the link inside `<name>` when `<name>` is already a directory.** The worktree had a tracked `tools/` directory, so the link meant to stand in for it became `tools/tools`, and `rm tools` refused. Check `test -e <name>` first, give `ln` the full destination path, and remove a link with `test -L <path> && rm <path>`.
- **Narrow an exclude to the thing being excluded.** The issue suggested `tools/**`; the SDK is at `tools/flutter`. The wider pattern applies in CI as well and would have hidden any Dart code later added under `tools/`. Caught by the cross-family review.
- **Decide on a reviewer's suggestions before opening the pull request.** A saved review can be reused for the post-PR pass only when the diff has not changed. Applying two one-line suggestions after the pre-PR review meant a second full review; applying them was still right, but it is a cost to weigh, and suggestions about files outside the diff can go in the docs pull request that follows.
- **Rebase a branch that has not been pushed when a docs pull request merges under it.** The lessons pull request for the previous issue changed the line next to one this branch changed in `CLAUDE.md`. Rebasing before the first push avoided a conflict at merge without breaking the rule against force-pushing.
- **This environment's clock runs slow against real time.** A goal check-in reported thirty minutes of waiting where `date` showed four. Do not judge whether a background review has stalled by `date`; compare the stream file's size between two checks.

## 2026-10-11 — PR #54 (issue #11, CI gates)

- **`flutter test --coverage` only records the libraries a test loads.** A new file that nothing imports is missing from `coverage/lcov.info`, and `diff-cover` skips a changed file it has no record for, so an untested new file passed the coverage gate. `test/all_libraries_loaded_test.dart` now imports every file under `lib/` and fails when one is missing. Found by the cross-family review, which reproduced it.
- **A file with no executable line has no coverage record even when it is loaded.** `lib/utils/constants.dart` is imported everywhere and absent from `lcov.info`. The reviewer's suggested fix (fail when a changed file is absent) would have failed every pull request that touches it. Check a suggested fix against the data before applying it.
- **`diff-cover` reads staged and unstaged changes, not untracked files.** To imitate a pull request that adds a file, `git add` it first, and `git reset` it afterwards.
- **To see a failure path run on the runner, use a throwaway draft pull request.** The artifact upload only runs when a step fails. A branch off the feature branch with one wrong golden baseline, opened as a draft titled DO NOT MERGE, showed the golden step failing and the artifact arriving in two minutes; then `gh pr close --delete-branch`. It keeps deliberate breakage out of the real pull request's history.
- **Get an action's commit from the API, never from memory.** `gh api repos/<owner>/<repo>/releases/latest --jq .tag_name`, then `gh api repos/<owner>/<repo>/commits/<tag> --jq .sha`.
- **The integration tests run on the emulator in about five minutes, and three fail.** `flutter test integration_test -d emulator-5554` builds the app once per test file. With no device it refuses to start, and in the host runner the audio plugin throws `MissingPluginException`. The three failures drag the launcher at board coordinates (#53).
- **Run `emulator -accel-check` before booting the emulator.** From this session it failed because `/dev/kvm` belonged to a group the session did not have, and the first attempt waited three minutes for a boot that was never coming. Starting it from a fresh session worked: put the command in a script and run `wsl.exe -d Ubuntu --cd / -- bash <script>`; `adb` from the original session then sees the device.
- **Pass a branch name to a workflow's shell through `env:`.** `${{ github.base_ref }}` expanded inside `run:` is pasted into the script; as an environment variable inside double quotes it is only ever data.

## 2026-10-11 — PR #57 (issue #13, toast position) and the PR for issue #14 (toast queue)

- **A position that is a number is tested at one screen size and one text size.** The first fix for #13 put the toast 112 px down on every screen and had four green tests. The cross-family reviewer measured it at 360x640, where it covered the menu's Play button, and at 1.6 times text size, where the header grew past it. When a layout fix is a constant, test it on a small phone and at double text size before calling it done, or measure the thing it depends on.
- **Let the screen that owns the content say where an overlay may go.** The toast overlay is above the Navigator and knows nothing about screens. `GameScreen` measures its header and calls `anchorToasts(this, height)`; everything else keeps the default. The anchor is owned, so a screen that finishes closing late cannot undo a newer one.
- **An ancestor cannot be rebuilt from a descendant's `dispose`, or from a layout notification.** Calling the overlay's `setState` from `GameScreen.dispose` throws "widget tree was locked"; `SizeChangedLayoutNotifier` sends its notification during layout, where it throws too. Both go through `WidgetsBinding.instance.addPostFrameCallback`.
- **A shared `LayerLink` was considered and rejected.** A `CompositedTransformFollower` would have followed the header with no measuring, but two game screens exist for a moment when the player goes back and straight into a new game, and a link with two targets asserts.
- **The test font is wider than the real one.** At 420 px wide the game header's row overflows by 18 px in a widget test and not on a device. Position tests use a 480x854 surface.
- **Fold an issue's lessons into the next pull request when the next issue is in the same area and does not restrict files.** It saves a docs pull request and a CI cycle; the lessons for #13 are in the pull request for #14.
- **Key a list item by its place in the sequence when the same value can appear twice.** The toast was keyed by the achievement's id, so the same achievement twice in a row reused a `State` that had already dismissed: invisible, never dismissing, and blocking the queue. A counter that advances on every dismissal gives each toast its own `State`.

## 2026-10-11 — PRs #59, #60 and the PR for issue #42 (level changes, background pause, idle loop)

- **Run one heavy job at a time on this machine.** A Gradle build, the emulator, a test run and a review at once, on a machine other sessions were also using, took the load average to 56: the emulator crashed, the WSL bridge timed out, a test run hit its timeout, and a profile build failed. Check `uptime` before starting a build or the emulator, and stop idle Gradle daemons with `android/gradlew --stop` (they hold about 1.5 GB).
- **Tell the opencode reviewer not to read outside the checkout.** It asked for permission to read the Flutter SDK in the main checkout, the request was rejected automatically, and the session ended after a few lines of narration with exit code 0 and no verdict. The prompt now says so.
- **When opencode's own probe says it is not answering, fall back to Codex at once.** `ask-opencode.sh --probe` exits 75 during an outage. `codex review --base origin/master --title "<criteria>"` reviews the branch; its answer is a short paragraph with no verdict line.
- **Prepare the next issue in its own worktree while a review runs, when it touches other files.** #20 and #41 were written and tested while #14 and #20 were with the reviewer, then rebased and pushed in turn. Do not do this with builds or the emulator (see the first point).
- **A profile build for the emulator is `flutter build apk --profile --target-platform android-x64 --no-tree-shake-icons`.** Without the last flag it fails on the non-constant `IconData` in the achievement model.
- **Measure CPU per thread from `/proc`, and expect no separate UI thread.** `/proc/<pid>/stat` fields 14 and 15 are the process's CPU ticks; `/proc/<pid>/task/*/comm` names the threads. This Flutter version runs Dart on the platform thread, so there is a `1.raster` thread and no `1.ui`; "everything except raster" is the Dart side.
- **On the emulator, rasterizing dominates, so a saving in Dart barely shows in the total.** Stopping the idle loop and the per-tick rebuilds cut the non-raster CPU of an idle game screen by about 40% and the total by about 18%, because the prize peg shimmer still redraws the whole board every frame in software. Report both figures and say which one a real device would feel.
- **A ticker that always runs makes every `pumpAndSettle` hang.** The board's peg ticker runs only while a peg is animating; a golden test that shows a shimmering prize peg pumps a fixed duration instead of settling.
- **Test repaint and rebuild separately.** `renderObject.debugNeedsPaint` right after a notification, before pumping, shows that something asked for a repaint. Comparing the `CustomPaint`'s painter object before and after shows whether the widget was rebuilt.
- **Remove a worktree's `test/**/failures/` images after regenerating goldens there.** They are git-ignored, so `git status` is clean, but a reviewer reads them as a failed run (see PR #48).

## 2026-10-11 — PRs #62 and #63 (issue #45, the top curve; issue #53, integration tests)

- **A sampled distance overestimates; use the exact one when the cost is the same.** The first check against the top curve took the nearest of 91 points. Codex pointed out that the true nearest point lies between samples, so a peg could pass that was too close. Distance to each segment between samples is exact for the polyline and costs no more.
- **A fingerprint of generated output proves "no level changed".** Hashing every peg of levels 1 to 300 before and after a change to the generator's check showed that the new rule rejected nothing that had been placed. Cheaper and stronger than reading diffs of layouts.
- **Read a background job's result before stopping what it depends on.** The emulator was killed while a run's output had not been read; the run had failed and the evidence of why was nearly lost. Read first, then stop.
- **An error thrown after a test completes fails the next thing the runner reports.** One integration run in three failed with a null check inside `just_audio`, raised after the test that caused it had finished. The cause was the app: sounds are not awaited, so a player disposed while loading threw into the zone. Look for unawaited futures in the app before blaming the test.
- **Integration tests use real time, so wait on a condition, never on a count of frames.** `pumpUntil` pumps until the game state says the ball has landed and fails with a message after a timeout. `pumpAndSettle` cannot be used on the game screen at all (see the lesson on tickers above).
